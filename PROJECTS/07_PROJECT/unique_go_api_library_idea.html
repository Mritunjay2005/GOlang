The Core Idea
Every Go API library — Gin, Fiber, Echo, Chi — still makes you think in HTTP. You write handlers, register routes, parse bodies, return status codes. You are still translating between HTTP and Go.

Axon flips this completely. You write normal Go functions. The library reads their signatures using reflection + generics at startup, generates the routing, serialization, validation, documentation, and transport layer entirely automatically. Your function signature is the API contract. Nothing else.

The transport layer is built directly on raw TCP + a custom framing protocol — not net/http, not fasthttp, nothing. Pure syscall and golang.org/x/sys (which is a Go team package, not a third-party library).
What it looks like to use
// You write this. Just normal Go functions.
type CreateUserReq struct {
    Name  string `validate:"required,min=2"`
    Email string `validate:"required,email"`
    Age   int    `validate:"min=18"`
}

func CreateUser(ctx context.Context, req CreateUserReq) (User, error) {
    // your business logic here
    return userService.Create(req)
}

func GetUser(ctx context.Context, id string) (User, error) {
    return userService.Get(id)
}

func ListUsers(ctx context.Context, page, limit int) ([]User, error) {
    return userService.List(page, limit)
}

// Axon reads these signatures at startup and does everything else:
//  → POST /create-user        (has request body)
//  → GET  /get-user?id=...    (single primitive arg)
//  → GET  /list-users?page=&limit= (multiple primitives)
//  → validates input automatically from struct tags
//  → serializes response to msgpack (binary) or JSON
//  → generates OpenAPI spec from function signatures
//  → error → structured error response, automatically

func main() {
    app := axon.New()
    app.Register(CreateUser, GetUser, ListUsers)
    app.Listen(":8080")  // starts on raw TCP, speaks HTTP/1.1 AND msgpack RPC
}

The killer features that make it unique
🔍
Reflection-free at runtime
Uses reflect only at startup to build a dispatch table. Zero reflect at request time — as fast as hand-written code.
📦
Dual protocol
Same function works over HTTP/JSON for browsers AND msgpack RPC for Go clients. Same port. Axon detects the protocol from the first byte.
📄
OpenAPI auto-generation
Generates a full OpenAPI 3.1 spec purely from Go function signatures and struct field tags. No annotations needed.
⚡
Raw TCP transport
Built on syscall-level epoll/kqueue. No net/http overhead. Custom framing protocol for the RPC path — much faster than HTTP.
🛡️
Compile-time safety
Axon validates function signatures at Register() time, not at request time. If your function signature is wrong, it fails at startup, not in production.
🔄
Streaming built-in
A function returning iter.Seq[T] (Go 1.22+) automatically becomes a streaming endpoint over the TCP transport.
Architecture layers (all from scratch)
Layer 1 — Transport (syscall level)
Direct epoll (Linux) / kqueue (macOS/BSD) via golang.org/x/sys. Custom framing: 4-byte length prefix + 1-byte protocol flag. No net/http. Handles keep-alive, backpressure, and zero-copy reads with a ring buffer.
Layer 2 — Protocol detection
First byte: 0x47 (G = GET) or 0x50 (P = POST) → HTTP mode. 0xAX prefix → Axon RPC mode (msgpack). Same connection can switch per request.
Layer 3 — Reflection registry
At startup, reads each registered function's in/out types. Builds a dispatch table: route string → (decoder func, handler func, encoder func). All closures, no reflection at runtime.
Layer 4 — Schema engine
Walks struct field types + tags once. Generates JSON Schema, OpenAPI paths, and validation closures. Validation runs at request time via pre-compiled closures, not reflection loops.

Weeks 1–3: TCP server + framing. epoll/kqueue event loop, accept connections, read framed messages into ring buffer. No HTTP yet — just raw bytes in, bytes out.

Weeks 4–5: Minimal HTTP/1.1 parser. Parse request line, headers, body from raw bytes. No spec compliance needed — just enough for JSON REST calls.

Weeks 8–9: Schema engine + validation. Walk struct fields once, compile validation closures, auto-decode request body into function arguments.

Weeks 10–11: Msgpack RPC codec. Write a minimal msgpack encoder/decoder (the spec is simple). Add protocol detection. Now one function serves both HTTP and RPC clients.

Weeks 12–14: OpenAPI generation + streaming. Generate spec from dispatch table. Add iter.Seq[T] return type → streaming response support.
